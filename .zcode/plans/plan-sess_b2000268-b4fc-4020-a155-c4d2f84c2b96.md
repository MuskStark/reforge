# SurveyJS 替换 ReForge 表单层实施计划

## 背景
停止自研表单维护，以 SurveyJS（`survey-core` + `survey-react-ui` @3.2.7，MIT 运行时，React 19 兼容已核实，内置简体中文本地化）承接流程收集表。已确认决策：**单页滚动、SurveyJS 原生渲染+主题化、直接替换旧组件**。

**不可破坏的契约**（来自调研）：
- `POST /api/processes` 后端 `DisallowUnknownFields` —— 提交体必须严格等于 Process 结构
- `mobileSupported`/`dataInteroperable` 三态布尔：`null`=未选择（条件必填的基础）
- 步骤/会签方/子步骤需稳定 32 位 hex id（`waitFor` 连线、流程图匹配硬依赖）
- FlowProcess 全字段被管理端与流程图消费，不可增删改；`GET /api/systems` 60s 缓存语义保留
- 页面耦合点（draft 统计、ChartSource 预览）由 SurveyJS 数据继续供给

## 步骤

### 1. 分支与依赖
- `git checkout -b feat/surveyjs-form`
- `cd frontend && pnpm add survey-core survey-react-ui`

### 2. 新增 `frontend/lib/survey/`（纯逻辑层，无 UI）
- **`schema.ts`**：构建 survey JSON。基本信息（name 必填 / applicant 选填 / description 选填，文案与现状一致）；`steps` dynamic panel（`renderMode: list` 单页滚动），面板内题目：
  - `name`（必填）、隐藏 `id` 题、`countersign` 开关、`mode` 线上/线下（visibleIf `countersign = false`）
  - `online.systemName`（sysselect，visibleIf mode=online）、`online.mobileSupported`（radiogroup 是/否，可见即必填）、`online.dataInteroperable`（radiogroup，显隐/必填/动态标题由事件重算）
  - `offline.documents`（taglist）、`offline.handlers`（dynamic panel：department + staff taglist）
  - `parties` dynamic panel（visibleIf `countersign = true`）内嵌 `subSteps` dynamic panel（name/mode/线上/线下，同主步骤结构）—— 三层嵌套
  - `waitFor.stepId` / `waitFor.partyId` 两个 dropdown（choices 事件重算）、`remark`
  - valueName 用嵌套路径（如 `"online.systemName"`），survey 数据天然呈 Process 形状；初始 `steps` defaultValue = `[emptyStep("", "step-initial")]`（`lib/types.ts` 现有工厂）
- **`mapping.ts`**：`surveyDataToDraft`（原始草稿 → 头部统计/流程图 ChartSource）、`draftToPayload`（提交清洗：`normalizeParty` 丢弃无名子步骤、waitFor 悬空清理/降级，逐行端口自 [flow-builder.tsx:156-171](/Users/phoebej/Develop/reforge/frontend/components/flow-builder.tsx)）
- **`validators.ts`**：逐条端口 [flow-builder.tsx:69-143](/Users/phoebej/Develop/reforge/frontend/components/flow-builder.tsx) `validate()`（全部规则与中文文案保持不变）+ `needsInterop` 重算（[step-checks.ts:59-69](/Users/phoebej/Develop/reforge/frontend/lib/step-checks.ts) 语义：紧邻前一步骤非会签且线上、双方系统名非空且不等）

### 3. 新增 `frontend/components/survey/`
- **`custom-questions.tsx`**：注册两个自定义题型（v3 `Serializer.addClass` + `ReactQuestionFactory`）：
  - `taglist` → 包装现有 [tag-input.tsx](/Users/phoebej/Develop/reforge/frontend/components/tag-input.tsx)（回车/逗号/去重/退格删除语义原样保留）
  - `sysselect` → 包装现有 [system-select.tsx](/Users/phoebej/Develop/reforge/frontend/components/system-select.tsx)（系统库下拉、60s 缓存、空库回退手动输入）
  - 若 v3 注册 API 有差异，按官方文档 Custom Question Types 章节调整
- **`flow-survey.tsx`**：替换 FlowBuilder 的主组件，**props 契约不变**（`value/onChange/onSubmitted/onPreviewChart`）。职责：
  - 构建 Model + `locale = "zh-cn"`；`onDynamicPanelAdded` 为新面板/会签方/子步骤分配 `genId()`（[lib/utils.ts](/Users/phoebej/Develop/reforge/frontend/lib/utils.ts)）
  - `onValueChanged` 重算：相邻异系统 → dataInteroperable 显隐+必填+标题「prev → cur 数据互通」；waitFor 两级下拉 choices（候选=索引更早的 countersign 步骤，文案「等待「i. name」会签」）
  - `onDynamicPanelRemoving`：steps 仅剩 1 个时阻止删除
  - 步骤上移/下移：panel 自定义 action + 数据数组换位（`survey.setValue("steps", reordered)`），换位后清理悬空 waitFor（端口 [flow-builder.tsx:52-66](/Users/phoebej/Develop/reforge/frontend/components/flow-builder.tsx)）
  - `onCompleting` 跑 validators 全量校验：失败 `toast.error` + `options.allow = false`；字段级必填由 SurveyJS 内建校验承接
  - `onComplete` 提交：`draftToPayload` → `POST /api/processes` → MultiStepLoader（沿用三段文案「校验流程数据/保存步骤与会签配置/写入 PostgreSQL」）→ toast 文案与现状逐字一致 → `onSubmitted()` → `survey.clear()` 重置回初始状态
  - 保留底部 LiquidGlass 按钮行（重置 / 一键生成流程图 / 白色实底提交流程，复用 [lib/glass.ts](/Users/phoebej/Develop/reforge/frontend/lib/glass.ts)）
- **`flow-survey.css`**：import `survey-core/defaultV2.min.css` + CSS 变量覆写映射品牌 token：`--sjs-primary-backcolor → #22d3ee`（--flow-line）、面板底色 → `--flow-panel`、文字 → `--flow-text`/`--flow-muted`、字体 → `--font-sans`、圆角/错误色对齐现有视觉

2. 启动 Go 后端 + `pnpm dev`，浏览器实测（含移动端 375px 视口）：
   - 基本信息 + 多步骤（线上/线下/会签+多方+嵌套子步骤）完整填写
